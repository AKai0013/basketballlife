# BasketballLife V9.1.1 多人共享世界驗收矩陣

## 目的與合格定義

本矩陣用來驗收 2～3 人共享世界的真正多人流程。合格不是只看到隊友狀態或共享年份，而是：

1. 所有真人在同一回合做出互相依賴的選擇。
2. 伺服器只生成一個共同、權威結果。
3. 每位玩家的個人後果、存檔與事件記憶只套用一次。
4. 重新載入、斷線、重連、重複送出或不同到達順序不得重複結算。
5. 共同回合仍發生在正式完整／精華生涯頁面，不得替換成另一套簡化生涯。

## 範圍與禁止項目

- 階段：production／maintenance 的 Preview 驗收。
- 測試環境：本機 Pages Functions＋本機 D1，或隔離 Cloudflare Preview＋`basketballlife-preview` D1。
- 禁止：正式 D1 測試資料、正式排行榜測試生涯、版本號變更、為了通過驗收而改寫核心公式。
- 本文件只建立驗收方法與證據欄位；所有項目預設為「未執行」，不代表已驗證。

## Preview D1 證據

將 `<ROOM_CODE>` 替換為本次房間代碼，只能對隔離 Preview D1 執行。

```sql
SELECT room_code, status, current_turn, updated_at
FROM online_key_battle_rooms
WHERE room_code = '<ROOM_CODE>';

SELECT cycle_number, chapter_number, COUNT(*) AS player_choices
FROM online_shared_choices
WHERE room_code = '<ROOM_CODE>'
GROUP BY cycle_number, chapter_number
ORDER BY cycle_number, chapter_number;

SELECT cycle_number,
       chapter_number,
       COUNT(*) AS player_rows,
       COUNT(DISTINCT event_id) AS authoritative_events
FROM online_shared_history
WHERE room_code = '<ROOM_CODE>'
GROUP BY cycle_number, chapter_number
ORDER BY cycle_number, chapter_number;
```

共同回合預期每位玩家最多一筆 choice，而同一 cycle／chapter 的 `authoritative_events` 預期為 1。重新載入、重複送出與重連後重跑查詢，數量不得額外增加。
